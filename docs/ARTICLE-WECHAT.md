# 正文（从这里开始复制到 Markdown 转换工具）

接手开源项目最怕什么？

不是代码烂，是**代码看起来很完整，跑起来才发现核心功能是坏的**。

最近我接手了一个零信任全栈脚手架。README 写得很漂亮：OIDC 鉴权、RBAC 权限、审计日志、限流、内置 AI 助手，"生产级、开箱即用"。

结果 `npm install` 第一步就挂了。

## 一、第一个坑：装不上

报错很直白：

```
npm error 404 'ollama-ai@1.0.0' is not in this registry
```

`package.json` 里声明了一个 **npm 上根本不存在的包**。也就是说，这个项目发布以来，没有任何人完整装起来过。

删掉这个幽灵依赖（还有一个从未被引用的 `ai` 包），装完依赖，往下走。

## 二、登录直接 500

界面能打开，点「使用 OIDC 登录」，服务端抛异常。

查代码发现：它调用的是 `client.randomPKCEVerifier()`——这是 openid-client **v6 的 API**，但项目锁定的是 **v5**。

v5 里这个方法在 `generators` 上，根本不在 client 实例上。**登录流程从第一天起就没跑通过。**

改成 v5 的正确写法：

```ts
const codeVerifier = generators.codeVerifier();
const codeChallenge = generators.codeChallenge(codeVerifier);
```

## 三、最隐蔽的两个坑

修完上面两个，登录终于「成功」了——审计日志清清楚楚记着 `auth.login ok:true`。

但怪事来了：**登录成功之后，所有 API 全部 401**。

页面能进，接口全拒。这种「看起来对但就是不行」的问题最难查。

### 坑 A：Cookie 被浏览器丢了

会话 Cookie 设置了 `secure: true`。

这个标记的本意是「只在 HTTPS 下传输」。但本地演示跑在 `http://127.0.0.1`——**浏览器会静默丢弃 Secure Cookie**，服务端以为设了，浏览器根本没存。

### 坑 B：localhost ≠ 127.0.0.1

另一个细节：登录回调落在 `127.0.0.1`，页面却停在 `localhost`。

**Cookie 按域名隔离**。一个写在 127.0.0.1，一个在 localhost 请求，自然拿不到。

两个都修掉，接口终于全部 200。

## 四、完整的坑位清单

前后一共修了 10 处，挑重点列一下：

【表：10 处缺陷一览】

| # | 问题 | 后果 |
|---|---|---|
| 1 | 依赖了 npm 上不存在的包 | 谁都装不上 |
| 2 | OIDC 用错版本 API | 登录 500 |
| 3 | 角色硬编码 member | 永远进不了管理页 |
| 4 | CSP 缺 unsafe-eval | **整个前端 JS 不执行，点按钮没反应** |
| 5 | Cookie secure + 域名不一致 | 登录成功但全接口 401 |
| 6 | 审计接口漏 await | 返回空对象 |
| 7-10 | 退出 405、缓存不失效等 | 体验类问题 |

其中第 4 个值得多说一句：**Next.js 开发模式 89% 的代码块依赖 `eval()`**，CSP 不放行就等于把整个客户端 JS 拦死了。页面是服务端渲染的所以能显示，但所有交互全部失灵——日志里连一条 POST 都看不到。

这种问题的排查思路就一条：**日志里「应该出现的请求没出现」，说明请求根本没发出去，问题在浏览器端，不在服务端。**

## 五、修完之后，补了三块真本事

光修 bug 只是恢复原状。这个项目号称"零信任"，但有个致命漏洞：

**JWT 签发之后、到期之前，撤不掉。**

员工离职、令牌泄露，攻击者还能用旧令牌访问 15 分钟。这不符合零信任"始终验证"的原则。

### 1. 会话即时撤销

签发时写入 `jti`，登出时进撤销表，校验时先查表：

```
签名 → 有效期 → 单令牌撤销 → 用户级撤销水位
```

还支持"一键踢出某用户全部会话"。

### 2. 资源级授权

原来的权限只能表达"能不能访问某类接口"，不能表达"**只能操作自己的文档**"。

补了一个 RBAC + ABAC 混合策略引擎：

- 普通成员只能读写自己的文档
- 跨租户访问一律拒绝，管理员也不例外
- 审计日志只读，谁都改不了

### 3. 链路追踪

每个请求分配 traceId，日志输出单行 JSON，出了问题能串起完整链路。

## 六、怎么证明它真能跑

口说无凭，上了 54 项自动化测试：

- JWT 签发验签闭环
- 授权策略 20 项断言（所有者/租户/deny 优先）
- 配置安全 30 项（CSP/Cookie/依赖完整性）

外加 API 集成测试：真打 HTTP 验证 401/403/200 三态，还有一条很关键的——

**登出之后，拿旧令牌重放，必须返回 401。**

这条过了，撤销机制才算真的生效。

再配上 GitHub Actions 双作业 CI，每次提交自动跑全套。
